Executive summary

We built a DAG workflow engine for code review (model nodes + deterministic script nodes; union / judge / proof-obligation / directed-rounds transitions; dual F1 + recall-weighted F2 scoring; an autoresearch loop) and swept the topology space. Findings:

  • Diverse specialists, unioned, is the recall engine. 5 independent lenses (security / correctness / concurrency / validation / edge-cases) merged → tripled recall over a single pass and beat the 0.355 union-of-3 baseline with one execution (FULL F1 0.44 / union-of-3 0.49).
  • Spend budget on resampling, not on more distinct lenses. Distinct-lens breadth saturates at ~5 (10 and 15 distinct lenses are flat). Re-running the same 5 lenses and unioning lifts recall sharply.
  • Direct the resampling and it wins. Telling later rounds "these are already found — look elsewhere" converts rediscovery-overlap into fresh coverage: REAL recall 0.67→0.82, REAL F2 0.52→0.58. winner
  • Every model-side precision lever failed. Judge/filter nodes delete recall; self-confidence is uncalibrated; proof-obligation (require a failing test) cuts hallucinations 4× but sacrifices too much recall. For a 12B model, precision must come from an external signal (static analysis / test execution), which the isolated-snippet benchmark can't run.
  • Frontier vs local: Haiku 4.5 single-pass = honest precision 0.39 but recall only 0.32 (13/43 real). The cheap local ensemble matches/exceeds frontier recall at $0 — it just trades precision and ~15× the calls. Implies a cheap-generator + strong-verifier pipeline.

Response curve — quality

REAL-set F2 vs LLM calls. Purple line = the gemma DAG scaling up (1→15 calls). Gold ★ = single passes of other models at x=1 — at one call, model quality spans a wide band, and the cheap-gemma DAG climbs past a Haiku single pass and toward Opus just by adding local calls. Grey squares = weaker gemma topologies at the same node count (shape > size).

Single-pass model ★ at 1 call: gemma 0.19, Haiku 4.5 0.29, GLM 4.7 (running), Opus 0.57 (precision circular). Diminishing returns on the gemma line: F2/node 0.090→0.013. N=10 directed = 89% of max at ⅔ cost.

Cost structure — by topology size

Per-review cost as a function of DAG size (AI nodes). Input dominates — each node re-sends the file (~15.7k input, ~0.12k output per call) — so both scale linearly with nodes. Cost assumes Vertex AI Flash-class token rates: $0.15 / 1M input, $0.60 / 1M output (locally it's $0; this is the hypothetical cloud cost of the shape). Pick the topology against this.

Per review at the recommended shapes: 5-lens union (5 nodes) ≈ 79k tok / $0.012 · directed R2 (10) ≈ 157k tok / $0.024 · directed R3 (15) ≈ 236k tok / $0.036. Prompt-caching the code prefix would cut the input term ~N× — the single biggest efficiency lever.

What worked / what didn't

Levers that help

union merge diverse lenses → recall
resampling repeat lenses ×N, union → more recall
directed rounds carry findings forward, "look elsewhere" → coverage

Dead ends

judge node filtering deletes recall
confidence gate gemma confidence uncalibrated
more distinct lenses saturates at 5
proof-obligation best precision, but recall collapses

Recommendation

Ship the directed-resampling panel (5 lenses × directed rounds). Pick the point on the curve by budget: R3 / 15 calls for max recall, R2 / 10 calls for the best cost-quality, 5-lens union when calls are scarce. For precision, pair it with a strong-model or test-execution verifier — the one lever that could cut false positives without losing recall, unblocked only on a buildable, runnable repo (the current isolated-snippet benchmark can't compile/run tests).
